# ReviewTrail network inventory

This inventory covers the installed `reviewtrail` source launcher, its browser reader and the two agent integrations. The last two tables identify calls made by separate upstream tools, build tools or the host application. Selection IDs refer to purposes. Two calls to GitHub can have entirely different purposes.

**Selected policy.** Keep GitHub review operations (K1–K3) and the configured LLM (K4). Remove the usage ping (N1), upstream starring (N4) and hosted guide publishing (N13). Portable guides (N14) are local HTML. The remaining review features below retain their existing destinations and triggers.

## Traffic that supports a review

| ID | Trigger and destination | What crosses the boundary |
|---|---|---|
| L0 | Open the local reader. Browser ↔ local ReviewTrail server on a random port. | Diff, guide passages, drafts, comments, local revision follow-up, settings and job status. Returning comments to the calling agent is a local handoff. The agent may include them in its next provider request. |
| K1 | Open, refresh or switch a GitHub PR, inspect references or browse files. GitHub REST/GraphQL through `gh`, including the configured GitHub Enterprise host. | Authenticated queries containing repository, PR/issue number, refs, paths or logins. Responses include source, discussion, checks and metadata. A PR can refresh while open. When a generated guide cites an unchanged caller, ReviewTrail reads the pinned head and merge-base locally first. A missing local blob can trigger a repository file request to the PR host for that revision and path. |
| K2 | Select a GitHub action such as submitting a review or replying to a thread. Same GitHub host. | Review text, chosen approval/change request, line or file anchors, and relevant PR/commit/thread IDs. Drafting an inline comment locally does not publish it. |
| K3 | Prepare a checkout for a GitHub PR (default), or explicitly fetch a GitHub remote. Git over HTTPS or SSH to the repository or fork. | Repository identity, negotiated refs and object IDs, credentials through Git's configured mechanism, and downloaded source. `--no-local` skips the checkout for a PR. |
| K4 | Generate a guide, ask a question, start another AI review or query a provider’s models. The chosen agent CLI/SDK, its configured LLM gateway and applicable auth endpoints. | Prompts, code/diff, question, relevant repository/tool context and model selection, depending on the action. Auth and discovery differ by provider. An ordinary local diff can be read without generating a guide. |

Implementation: [review API](packages/server/review.ts), [GitHub operations](packages/shared/pr-github.ts), [CLI checkout](apps/review/server/index.ts), [guide generation](packages/server/guide/guide-review.ts), [AI providers](packages/ai/providers), [Pi handoff](integrations/pi/index.ts).

## Choices in the reader and inherited release code

| ID | When and where | Data or consequence |
|---|---|---|
| N1 | Removed usage telemetry. | The daily ping sender, release wiring and telemetry service have been deleted. |
| N2 | Removed upstream release discovery while extracting the source launcher. | Update the checkout and rebuild locally. |
| N3 | Removed the upstream installer and update endpoints. | The source installer links the local ReviewTrail command and agent integrations. |
| N4 | Removed the upstream star prompt and its API. | ReviewTrail never checks or changes the reviewer’s GitHub star on the upstream project. |
| N5 | **Local Git remote probes.** Enabled by default for applicable repo reviews on startup or when recomputing the diff. `git ls-remote --symref origin HEAD` goes to the configured origin, including non-GitHub SSH hosts. | Repo, auth exchange, remote HEAD and tip. Can activate an SSH key even on a staged-only review. Use `--no-git-remote-check` or `REVIEWTRAIL_GIT_REMOTE_CHECK=0` to skip the automatic probe and retain manual fetch. [Git detection](packages/shared/review-core.ts), [review lifecycle](packages/server/review.ts) |
| N6 | **GitLab.** Review a GitLab MR, follow a GitLab reference, prepare a checkout or submit feedback. GitLab.com or the configured enterprise instance via Git, `glab` and the instance API. | Project, MR/issue IDs, refs, file reads and, on submission, comments or review actions. [GitLab adapter](packages/shared/pr-gitlab.ts), [reference cards](packages/shared/ref-cards.ts) |
| N7 | **Bitbucket.** Review a Bitbucket Cloud PR or inspect a supported reference. `api.bitbucket.org/2.0` and the Git remote for a checkout. | Authenticated repository/PR/file queries and explicit review writes. [Bitbucket adapter](packages/shared/pr-bitbucket.ts) |
| N8 | **Author pictures.** Commit/PR views resolve and render avatars. GitHub/GHE, GitLab and image hosts returned by the provider, including GitHub's avatar CDN or Gravatar. | GitHub local-commit enrichment queries commits by repo. GitLab’s lookup **sends author emails** as query parameters. The browser subsequently requests the image URL. Initials can replace this feature. [Commit avatars](packages/shared/commit-avatars.ts), [reference cards](packages/shared/ref-cards.ts) |
| N9 | **PR attachments, embedded media and external links.** Views can fetch GitHub attachment/raw/media hosts, a signed storage redirect, or an origin referenced by rendered content. Some GitHub attachment probes request a single byte to determine media type. Clicking a link opens its destination separately. | Referenced URL/path and connection metadata. Private forge attachments may use the local authenticated proxy. Remote image or HTML subresource URLs can contain identifying values. Rendering behavior depends on the view and content. Can keep GitHub attachments while blocking arbitrary third-party assets. [Attachment policy](packages/shared/pr-artifact-document.ts), [video probe](packages/review-editor/components/PRDescriptionVideo.tsx), [HTML embed policy](packages/core/html-embed.ts) |
| N10 | **Dependency metadata.** Opt-in package card lookup to `registry.npmjs.org` and `api.npmjs.org`. | Eligible dependency names for metadata and weekly download counts. Routing rules filter known private packages. Existing off switch is `REVIEWTRAIL_PACKAGE_LOOKUP=0`. [Package lookup](packages/shared/package-metadata.ts) |
| N11 | **Call Flow downloads.** Enabling Call Flow permits on-demand installation of its runtime and missing language packs. The installer fetches a pinned CallDiff archive from GitHub and dependency tarballs from lockfile URLs (normally the npm registry). Off in a fresh config. | Registry/tarball requests for analysis packages and the selected language parsers. Analysis then runs locally. Preinstalling the packs is an alternative to allowing downloads during a review. [Downloader](packages/shared/call-flow.ts), [language packs](packages/shared/call-flow-languages.ts) |
| N12 | **Fonts.** Choosing a hosted diff font loads Google Fonts CSS and font files (`fonts.googleapis.com`, `fonts.gstatic.com`), or Hack from `cdn.jsdelivr.net`. A saved choice can load again on later sessions. | Font name and ordinary browser request metadata. The default diff font works locally. [Font loader](packages/ui/utils/diffFonts.ts) |
| N13 | Removed hosted guide creation and revocation. | Saving, exporting and deleting a guide operate locally. SSH launch also no longer creates a share URL for the raw diff. |
| N14 | Download a guide as a single HTML file from the local server. | The file includes the retained patch, source excerpts, notes, chapter navigation and snapshot metadata (including any guide instructions). Opening it requires zero HTTP requests. [Offline document](packages/core/offline-guide.ts) |
| N15 | **Tailscale.** Selecting `--tailscale` or enabling it in ReviewTrail’s environment or config publishes the session through the local Tailscale daemon and tailnet. | Peers with access can receive the review. Control, peer and relay destinations follow the daemon’s configuration. [Tailnet serving](packages/server/tailscale-serve.ts) |
| N16 | Explicit Cloudflare Access integration. | Reads a running tunnel’s registry and access configuration from the specified data directory. The connector and its Cloudflare traffic belong to that external installation. [Tunnel handoff](packages/server/session-cf-access.ts) |
| N17 | **Remote/SSH listening.** For a local Desktop or Pi launch the server binds locally. SSH detection or explicit remote mode binds to `0.0.0.0` and allows access through a forwarded port or network interface. | Inbound access to the review UI/API. Set `REVIEWTRAIL_REMOTE=0` to force local mode. [Remote detection and binding](packages/server/remote.ts) |

## Removed upstream applications

The review checkout excludes the Inbox, mobile pairing and push relay, Spaces, marketing site, hosted plan and guide portals, short-link and feedback workers, URL annotation, and notes-app export integrations. Their former U1–U10 operations have no product entry point here. Markdown rendering, local drafts and diff annotations still support code review.

## Traffic controlled outside ReviewTrail

| ID | Owner and trigger | Destinations and data |
|---|---|---|
| H1 | Install/build/update tooling | Bun/npm resolve dependencies and fetch package names, versions and tarballs from the registry or configured mirror. Git dependencies and host/tool downloads can contact GitHub or the configured tool vendor. The ReviewTrail symlink installer operates locally after dependencies and UI are built. [Lockfile](bun.lock), [installer](scripts/install-reviewtrail.ts) |
| H2 | Claude Code Desktop, Claude Code CLI, account and configured extensions | Inference and auth, plus potential host-managed updates, diagnostics, feature/config sync, connectors/MCP and remote sessions. Exact hosts depend on the account, deployment, enabled features and organization policy. These requests belong to the host even when the fork is installed. [Desktop configuration](https://code.claude.com/docs/en/desktop), [Claude Code network configuration](https://code.claude.com/docs/en/network-config) |
| H3 | Pi agent 0.84.4 | Startup can check `pi.dev/api/latest-version`, report install version to `pi.dev/api/report-install`, check installed packages, or download missing tool binaries such as ripgrep from GitHub Releases. Pi documents `--offline` / `PI_OFFLINE=1` for startup networking and `PI_TELEMETRY=0` for install telemetry. Model calls, user-invoked tools, extensions and explicit package commands have their own network behavior. Verified against the installed Pi CLI and its version-check and interactive-mode code. |
| H4 | Browser, OS, Git, credential helpers and agent tools | An external link targets the URL the reviewer opens. Credentials may use SSO/token refresh, Git can use SSH proxies, LFS or custom remote helpers, installed forge CLIs can check for their own updates, and agents may use a configured web tool or MCP service. DNS, proxy and certificate services follow workstation policy. An enforced destination allowlist must also cover these processes. |

## Verification and selection

A production-browser run opened the 58-file, 2,388-line patch, generated a guide through a local stand-in for Claude, expanded code, navigated between behaviors, saved progress, switched to the diff and opened a line comment. The browser attempted **zero external HTTP(S) origins** across **44 distinct loopback paths**. The run used a static patch and local provider. Authenticated GitHub, live provider sessions, cold installs, release builds and the Desktop process were outside that capture. The other rows come from inspection of source paths, subprocess commands and browser asset loaders. Configurable origins and user-provided URLs make this a call-type inventory, not an exhaustive list of possible DNS names.

A separate run downloaded the 58-file guide and closed the server. Chromium opened that file with networking and JavaScript disabled. It made zero HTTP requests, and the chapters, line explanations and full diffs remained readable. This capture covers that fixture. Avatars, custom fonts, forge content and optional tools have the other network behaviors listed above.
